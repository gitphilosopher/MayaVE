### Features
- **AutoPhage 2.0 Phase 5 — Single-Issue Mode A & Minimalist Rich CLI/TUI (`skills/maintenance/macro/cli.py`, `skills/maintenance/macro/tui.py`, `autophage.py`)** — Implemented the user-facing interface, single-issue Mode A execution, and keyboard-first Claude Code-style Rich TUI for AutoPhage 2.0:
  - *Unified CLI command suite (`AutoPhageCLI`)*: Implemented CLI subcommands: `autophage scan` (progressive repository discovery and Markdown backlog creation), `autophage fix <findings.md>` (multi-issue Mode B campaigns), `autophage fix --issue <id>` (single-issue Mode A execution), `autophage improve` (read-only improvement discovery requiring operator authorization), `autophage review` (read-only branch or diff security inspection), `autophage status` (campaign state, active worktrees, and model health), and `autophage resume` (safe campaign recovery).
  - *Single-issue Mode A execution (`CampaignEngine.execute_single_issue`)*: Enables isolated repair of individual issues from Markdown findings files without bypassing campaign engine safeguards (worktree isolation, structured planning, quality gates, reviewer safeguards, independent review, and durable checkpoints).
  - *Claude Code-style Rich TUI & palette compliance (`MacroTUI`)*: Compact, keyboard-first interactive terminal shell (`macro> `) adhering strictly to the mandatory palette (Purple `rgb(180,156,255)`, Gray `rgb(160,157,165)`, White, Mint `rgb(128,222,184)`, Amber `rgb(244,201,125)`, Coral `rgb(255,128,146)`). Supports slash shortcuts (`/scan`, `/fix`, `/status`, `/resume`, `/review`, `/improve`, `/help`, `/quit`), real-time streaming task step outputs, and graceful non-interactive fallback when `not sys.stdin.isatty()`.
  - *Model policy compliance & preflight health probing (`check_model_availability`)*: Probes and reports exact availability for Planner (`qwen3.5:4b` on Ollama), Tier 1 (`qwen2.5-coder:3b` on Ollama), Tier 2 (`Antigravity` CLI / `agy.exe`), and Independent Reviewer (`copilot.exe`), reporting unavailable workers clearly instead of silently substituting models.
  - *Full backwards compatibility*: Preserves existing legacy coordinator flags and entry points (`skills/maintenance/coordinator.py`, `.maya/maintenance/coordinator.py`) while routing AutoPhage 2.0 subcommands cleanly, and provides a root runner script (`autophage.py`).
  - *Focused test coverage*: Verified with 11 focused unit and mock integration tests in `.maya/tests/maintenance/test_macro_cli.py` (total 56 tests passing across Phases 1–5 in 2.33s).
- **AutoPhage 2.0 Phase 4 — Markdown Campaign Engine (Mode B) (`skills/maintenance/macro/campaign.py`)** — Implemented the multi-issue autonomous campaign execution engine for MACRO:
  - *Markdown ingestion & phase-3 backlog compatibility (`CampaignEngine.ingest_markdown`)*: Ingests structured multi-issue Markdown backlogs generated by Phase 3 progressive discovery or manual issue curation using `parse_markdown_backlog`, with header normalization (`[ISSUE-ID]` and `ISSUE-ID:`) to preserve issue IDs, severities, risks, target files, and test targets without detail loss.
  - *Dependency ordering & cycle detection (`topological_sort_tasks`)*: Computes deterministic execution order respecting inter-task dependencies, detecting circular dependencies fail-closed to prevent deadlock.
  - *Structured CPU-first planning (`CampaignPlanner`)*: Uses configured Planner model (`qwen3.5:4b` default) or deterministic fallback to produce compact 4-step plans prior to isolated code execution.
  - *Atomic state machine & campaign resumption (`CampaignStateManager`)*: Durable, recoverable state tracking in `.maya/maintenance/campaign_state.json` (`PENDING` -> `PLANNING` -> `IN_PROGRESS` -> `VERIFYING` -> `REVIEW_PENDING` -> `READY_TO_INTEGRATE` / `NEEDS_APPROVAL` / `FAILED` / `BLOCKED`), using atomic file replacement (`.tmp` + rename) and corruption recovery. Automatically skips already verified tasks on campaign resumption.
  - *Isolated per-issue execution & laptop resource safety*: Executes one task at a time in dedicated isolated Git worktrees via `WorktreeManager`, adhering strictly to RTX 3050 laptop CPU/VRAM constraints.
  - *Three-tier model routing & authorization gating*: Routes low-risk tasks to Tier 1 local MACRO (`qwen2.5-coder:3b`), while escalating high-risk, architectural core modules, or repeated attempts to Tier 2 cloud agent (`AntigravityAgentAdapter`). Halts and requests operator authorization (`TaskStatus.NEEDS_APPROVAL`) if Tier 2 is unauthorized.
  - *Mechanical quality gates & pre-review security safeguards*: Enforces `QualityGateEngine` deterministic verification (diff bounds, non-weakened assertions, local test policy, pytest) and `ReviewerSafeguardScanner` diff security checks (blocking unauthorized network access, shell commands, credential leaks, or governance tampering) before external review.
  - *Independent code review & bounded correction cycles*: Integrates read-only `CopilotReviewerAdapter` code review with bounded correction attempts (max 2), recovering when reviewer feedback is resolved or holding for operator approval on rejection.
  - *Absolute safety on mainline integration*: Enforces zero automatic merging into `main`. Successfully verified tasks transition strictly to `READY_TO_INTEGRATE` awaiting explicit operator action.
  - *Focused test coverage*: Verified with 10 unit and mock integration tests in `.maya/tests/maintenance/test_macro_campaign.py` (total 45 tests passing across Phases 1, 2, 3, 4) with zero network dependency.
- **AutoPhage 2.0 Phase 3 — Repository Intelligence & Progressive Discovery Engine (`skills/maintenance/macro/discover.py`)** — Implemented the 5-stage repository intelligence and progressive discovery subsystem for MACRO:
  - *Bounded repository mapping & taxonomy (`RepoMapper`)*: Builds structured repository inventories categorizing files across MayaVE subsystems (`core`, `brain`, `services`, `skills`, `config`, `frontend`, `scripts`, `audio`), discovers Python AST symbols and JS/TS declarations with syntax error tolerance, maps tests under `.maya/tests/` to source modules, identifies entry points, and extracts cross-subsystem dependency relationships while strictly ignoring non-code exclusions (`.git`, `.venv`, caches, worktrees, reports).
  - *Mechanical static scanner (`MechanicalScanner`)*: Deterministic, model-free static analysis detecting unhandled syntax errors (`MECH-SYNTAX`), swallowed exceptions with bare pass/continue (`MECH-EXC`), and unsafe subprocess or `os.system` shell calls (`MECH-SEC`) with exact file and line references.
  - *Read-only architectural safety & tool registry (`create_discovery_registry`)*: Restricted discovery agent registry providing only read-only exploration and verification tools (`fs_read`, `fs_search`, `fs_find_symbols`, `test_runner`, `finding_record`), deliberately omitting `fs_edit` and `fs_write` to strictly guarantee zero mutation of production source code or maintenance ledgers.
  - *Evidence verification & anti-fabrication (`EvidenceVerifier`)*: Validates that referenced target files exist on disk, verifies line bounds and test targets, and downgrades unverified claims to `UNVERIFIED`/`SPECULATIVE` to prevent false defect claims.
  - *Deduplication, severity ranking & Markdown backlog export*: Deduplicates findings using location/symbol fingerprints, ranks by severity (`P0` -> `P1` -> `P2` -> `P3`) and confidence (`CONFIRMED` -> `PROBABLE` -> `SPECULATIVE`), and formats reports into Markdown backlog format 100% consumable by `skills.maintenance.manifest.parse_markdown_backlog` for Phase 4 campaign intake.
  - *Mock test verification*: Verified with 10 focused unit and integration tests in `.maya/tests/maintenance/test_macro_discovery.py` (total 35 passing across Phases 1, 2, 3) with zero network dependency.
- **AutoPhage 2.0 Phase 2 — MACRO Autonomous Reasoning Loop & Local Model Adapter (`skills/maintenance/macro/agent.py`)** — Implemented the bounded autonomous reasoning loop and context management engine for MACRO:
  - *Autonomous Think-Tool-Observe-Reflect loop (`MacroAgent`)*: Implemented multi-turn agent loop driving local Ollama inference (`qwen2.5-coder:3b` default), tool call parsing (`ToolCallParser` supporting balanced-brace JSON extraction, markdown fenced blocks, and plaintext JSON), execution dispatch via `MacroToolRegistry`, structured observation feedback, and reflection.
  - *Context budget & progressive sliding window (`MacroContextManager`)*: Built deterministic token-conscious context manager with pinned system prompt, pinned original task objectives, and 4-pass progressive compression (Pass 1: full turns; Pass 2: trim oldest observation outputs to 300 chars; Pass 3: prune oldest intermediate assistant thoughts; Pass 4: trim even recent observations if needed) to maintain context strictly within budget (default 8,192 chars / ~2,048 tokens).
  - *Execution guards & failure resilience*: Configurable max turns (default 25) and wall-clock timeout (default 300s), active cancellation checking (`is_cancelled`), single-execution concurrency lock (`threading.Lock`), repeated failed tool call loop prevention (consecutive identical error threshold), unknown tool feedback, and malformed model response recovery with model reprompting.
  - *Zero network mock test coverage*: Verified with 10 focused unit and integration tests in `.maya/tests/maintenance/test_macro_agent_loop.py` (total 25 passing across Phase 1 & 2) with zero network dependency.
- **AutoPhage 2.0 Phase 1 — MACRO Tool Registry & Execution Engine (`skills/maintenance/macro/tools.py`)** — Implemented the foundational, typed tool execution layer for MACRO, MayaVE's autonomous maintenance agent:
  - *Typed tool registry (`MacroToolRegistry`)*: Central registry providing typed parameter schemas (`ToolParameter`, `ToolDefinition`, `ToolResult`), schema export for model tool calling, and exception-isolated dispatch.
  - *Initial tool suite*: Implemented 8 core tools: `fs_read` (line-range selection, line-numbered formatting, character bounds), `fs_search` (path/glob filtering, directory exclusions, regex/text search), `fs_find_symbols` (Python AST symbol extraction, JS/TS declaration extraction, non-fatal syntax error tolerance), `fs_edit` (strict exact-match requirement rejecting stale or ambiguous matches, CRLF/LF line ending preservation), `fs_write` (safe creation, recursive parent directory creation, overwrite protection), `git_diff` (path filtering, bounded output, error reporting), `test_runner` (focused pytest execution under `.maya/tests/`, JUnit XML parsing, timeout handling, non-shell execution), and `finding_record` (typed finding classification preserving issue IDs).
  - *Filesystem containment & worktree safety (`PathGuard`)*: Strict path validation confining all file reads and writes to the assigned worktree (`.maya/worktrees/<task_id>`) or allowed read-only repository root, with an explicit write exception for `docs/CHANGELOG.md`. Rejects path traversal (`..`), alternate Windows drive paths, symlink/junction escapes, and any access to `.git/` internals or protected state files (`.env`, `state.json`, `cache.json`, `approvals.json`).
  - *Sandboxed subprocess execution (`run_sandboxed_command`)*: Bounded subprocess execution with `shell=False`, strict `cwd` confinement, configurable timeouts, and output limits.
  - Covered by 15 focused regression tests in `.maya/tests/maintenance/test_macro_tools.py`.
- **Autophage Phase 5 deterministic reviewer safeguards & tier diff limits** — Implemented pre-review security scanning and tier-based diff limits on candidate patches before invoking external code reviewers:
  - *Pre-review security scan*: Deterministic analysis scanning candidate diff hunks and ASTs for newly introduced network access (`NET001`), subprocess execution / `shell=True` / `os.startfile` (`SUB001`), package manifest/dependency changes (`DEP001`), credential/API key leaks (`SEC001`), suspicious deletions of tests/assertions/security gates (`DEL_*`), and maintenance governance modifications (`GOV001`).
  - *Tier-based diff limits*: Enforces risk-tier boundaries (`LOW`: 2 files / 80 lines, `MEDIUM`: 5 files / 250 lines, `HIGH`: 10 files / 600 lines, `VERY_HIGH`: 20 files / 1200 lines) with per-file limits; diffs exceeding limits hold for human review.
  - *Secret redaction & approval binding*: Automatic regex redaction (`[REDACTED_SECRET:<hash>]`) masks sensitive tokens across findings, trace events, and permission requests; holds trigger `TaskStatus.NEEDS_APPROVAL` bound to the exact `patch_sha256` and ruleset, invalidating prior approvals if the patch changes.
  - *Defense-in-depth reviewer fail-closed*: `CopilotReviewerAdapter.review` scans the diff before launching CLI processes and fails closed with `NEEDS_HUMAN_APPROVAL` if safeguard violations are detected.

- **MayaNode event/memory producer + outbox sync (Step 3)** — `services/node/events.py::record_event()` and `services/node/memory_producer.py::record_memory()` are the only application-facing entry points for data bound for MayaNode: both validate locally (`services/node/protocol.py`), stamp a UTC timestamp and a unique `event_uid`, and queue into a new durable local outbox (`services/node/outbox.py`, `~/Maya/Node/outbox.json`, atomic `.tmp` + replace) rather than calling `/sync` directly. `NodeSyncManager._sync_once` now pulls up to `config.node.max_events_per_sync`/`max_memory_per_sync` pending items per round, pushes them alongside the cursor, and reconciles the outbox against the response — only items the server actually settled this round (any terminal event status; the exact `(key, updated_at)` pair sent for memory) are removed, so a batch cap, a mid-round crash, or Node staying offline never loses queued data; the cursor still only ever advances per the Step 2 contract. Adds the first real MayaVE event type, `mayave.turn_completed` (`{intent: string}`), registered identically on both sides; `protocol.ping` is unchanged. `config.node.enabled` still defaults to `False`, and recording events/memory never depends on the sync manager running or Node being reachable.
- **MayaNode inbound memory merge** — `NodeSyncManager._apply_incoming_changes` hands `changes["memory"]` to `ContextManager.apply_remote_memory_changes`, which accepts only `semantic_memory:*` keys, re-embeds locally, dedups against the existing store and inserts with `source="mayanode_sync"`; outgoing, `_sync_memory_to_node` mirrors only `user_stated` fact/preference memories (no embeddings, no compaction summaries). Incoming `changes["events"]` are intentionally not applied.
- **MayaNode versioned protocol layer** — `services/node/protocol.py` implements the contract in `docs/PROTOCOL_CONTRACT.md` (`protocol_version=1`, envelope validation, event-type registry, request builder, response version check, change-ordering check); `NodeClient.sync` validates outgoing events and the response (`SyncResult.from_response`) and adds `health()`.
- **MayaNode discovery + sync scaffolding** — `services/node/` (`discovery.py`, `client.py`, `identity.py`, `sync_state.py`, `sync_manager.py`) adds discovery (`GET /status` probed against a configured `base_url` then an ordered candidate list), connection (`POST /heartbeat`), and an empty-payload `POST /sync` loop that persists/advances a cursor (`~/Maya/Node/sync_state.json`, atomic `.tmp` + replace) and a stable `device_id` (`~/Maya/Node/device_id.txt`) across restarts. `NodeClient` is auth-ready (`Authorization: Bearer` header hook, unused by MayaNode today). `node_sync_manager` runs as a background task in `main.py`, backoff-guarded and never raising even when MayaNode is offline or `config.node.enabled=False` (default). Step 1 itself wired no application data through; Steps 3–4 above add it.
- **Shutdown and restart skill** — `skills/system/power.py` now handles the `shutdown`/`restart` intents (previously answered by the LLM, nothing happened) by asking "say yes to confirm"; `Router.dispatch` calls `resolve_pending` first so a one-shot request (30 s TTL) is confirmed, declined or dropped by the next utterance, and confirm runs `shutdown /s` or `/r /t 10` (no `/f`) in the executor.

### Architecture
- **Merged intents** — `open_app`/`open_website` → `open_target`, `note_create`/`note_append` → `note_write`, `note_read`/`note_list`/`note_open` → `note_view`, `set_reminder` → `set_timer`; skills decide the sub-operation from wording and `dataset_tools migrate-legacy-intents` relabels retired ids across splits and candidates. `help` and `unknown` are live intents again (see `docs/CONTRIBUTING.md`).
- **Config-driven command registry** — `config/command_domains.json` (25 `domain.operation` entries with entities, `target_mode`, `requires_confirmation`, semantic seeds) is a projection of the skill-mode intents in `datasets/intents.json`; `CommandRegistry`/`load_specs` validate it at load and reject a seed shared by two operations; the vector corpus is fingerprinted against it and a stale corpus only warns.
- **Command-level retrieval** — semantic scoring collapses per-seed vectors to one score per `domain.operation` before the top-k cut; margin is best minus second-best distinct command (`schemas.aggregate_by_command`).
- **Listening state broadcast** — `main.on_speech` broadcasts `state:listening` only when Maya is not PROCESSING/SPEAKING, empty STT resets to IDLE with baseline behavior, and the FSM no longer overwrites an in-flight turn, giving the sequence `listening → processing → speaking → idle`.

### Issues
- **Classifier failure log growth and Git tracking** ([#30](https://github.com/owner/repo/issues/30)) — [Verification pending] The current worktree contains changes to redirect new failure records to a local path and bound retention, plus local regression tests. The available test reports predate these changes, so the tracked-log privacy and growth fix is not yet marked resolved.
- **LLM fallback confidence contract** — [Potential; runtime-unverified] Missing or malformed confidence is deliberately treated as 0.0 by `validate_raw_llm_output`, while the fallback prompt requires a numeric confidence. The previously cited `diag_llm_seed*.txt` files are absent; verify actual model outputs before changing this fail-closed behavior.
- **Power confirmation and countdown** — [Potential] Confirmation is one-shot and accepts a bare confirmation phrase; a 10-second OS shutdown/restart countdown has no voice abort. No unintended power action is demonstrated; decide whether cancellation during the countdown is a product requirement before changing the flow.
- **Wake window boundary** — [Potential; static behavior] Wake recognition uses fixed, non-overlapping two-second windows, so a phrase split across windows may be missed. Runtime frequency has not been established.
- **Sparse classifier classes** — [Validation pending] In the current data snapshot, 28 of 41 intents are below their `min_examples` target. The cited recall/accuracy metrics are stale, and `datasets/training/candidates.jsonl` is currently empty; measure current per-class performance before changing training data.
- **Skill dispatch interruption gap** — [Limitation] Skill work before its first speech call is not registered as an interruptible task; a barge-in or sleep request may not cancel in-flight pre-speech work.
- **Critical-path latency** — [Potential; current impact unmeasured] Semantic-memory embedding can precede the first LLM token when memories exist, and streamed speech waits for per-phrase playback completion. Existing timing instrumentation can be used to establish impact before optimization.
- **Node backlog drain rate** — [Conditional limitation] Sync uploads at most 200 events and 200 memory keys per round and waits for the configured interval between successful rounds. Node sync is disabled by default; no material backlog is demonstrated.
- **Recent conversation window is not persisted** — [Limitation] The 50-entry recent history is in-memory and is lost on restart; durable semantic memory follows a narrower write policy.

Accepted limitations (not active defects): Inputs of three tokens or fewer may be decided by keyword rules before the classifier; the active router uses `CommandUnderstander`, while `HybridIntentEngine`, `shadow_mode` and `hybrid_domains` remain an unwired compatibility surface; the local embedding provider auto-seeds a stale command corpus; `media.mute` stays on the legacy route; Google STT is online-only; idle fidget tuning, screen-attention input and extra VRMA animations are optional/manual-only.

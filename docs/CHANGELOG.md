# CHANGELOG

All notable changes to MayaVE are documented here.

## [Unreleased]

### Features
- **AutoPhage Autonomous Maintenance Subsystem (Archived to `.maya/maintenance/`)** — Completed local-first autonomous codebase maintenance architecture featuring split-role Qwen execution, bounded `ApprovalManager`, durable `MaintenanceLedger`, and an independent `Auditor`/`AggregateReviewer` gate. Relocated completely from `skills/maintenance/` to `.maya/maintenance/` to isolate maintenance internals while preserving 100% resumption capability, branches, and ledgers documented in `docs/AUTOPHAGE_RESUMPTION_GUIDE.md`.
- **Power Shutdown Cancellation (`skills/system/power.py`)** — Resolved Issue #461 by implementing `cancel_shutdown()` invoking `shutdown /a` to abort pending OS shutdown or restart countdowns with fail-closed error handling. Registered under `cancel_shutdown` intent in `brain/router/dispatch.py` and verified by 4 targeted tests in `.maya/tests/skills/system/test_power_cancellation.py`.
- **Vector Embedding Identity Protection (`brain/vector_store.py`)** — Persisted `embedding_model` and `dimensions` in the `memories` table via backward-compatible additive SQLite migration to prevent comparing incompatible vectors. Hardened `VectorStore.search` to safely skip mismatched dimensions, incompatible identities, and malformed BLOBs; verified by 6 tests in `.maya/tests/brain/test_vector_identity.py`.
- **Hybrid Semantic Router activated as runtime default** — `RouterConfig.backend` in `config/settings.py` now defaults to `"hybrid"`. `Processor._classify` routes commands through `CommandUnderstander` (`brain/router/understand.py`), producing a `CommandIR` (`READY`/`NEEDS_CLARIFICATION`/`UNKNOWN`/`REJECTED`) that bridges to `Router.dispatch` via `to_legacy_intent(ir)`. The legacy classifier (`IntentEngine`) remains available as a fallback backend. `HybridIntentEngine` (`brain/router/hybrid_engine.py`) is preserved as an unwired compatibility wrapper with shadow mode.
- **CUDA-accelerated Kokoro neural TTS** — Migrated virtual environment to official PyTorch CUDA build (`torch==2.14.0+cu126`). `TTSConfig.device` in `config/settings.py` now defaults to `"auto"`, resolving dynamically to CUDA when `torch.cuda.is_available()` is True and falling back cleanly to CPU otherwise. Verified concurrent execution on NVIDIA GeForce RTX 3050 Laptop GPU (4GB VRAM) coexisting with Ollama `llama3.2` without CUDA OOM, model eviction, or stability issues in tested workload.
- **Command IR router pipeline** — `brain/router/understand.py::CommandUnderstander` produces a `CommandIR` (`READY`/`NEEDS_CLARIFICATION`/`UNKNOWN`/`REJECTED`, `brain/router/ir.py`) through context rewrite (`context.py`) → guards → classifier confidence+margin gate → semantic retrieval (`semantic_router.py`, `command_vector_store.py`, separate SQLite file + fingerprint sidecar) → LLM fallback (`llm_fallback.py`, validated by `validate.py` against `config/command_domains.json`) → deterministic entity extraction (`entities.py`). A low-confidence command ends `UNKNOWN`, never a forced intent.
- **Router evaluation tooling** — `brain/router/eval_router.py` (retrieval sweeps, `--seed` for the command corpus), `eval_ir.py` (false-execution rate as primary metric, per-case output, `model_digest`), `failure_matrix.py` (cross-seed failure frequency), `diag.py`, and `datasets/router_eval/cases.jsonl` (60 cases); multi-seed run outputs are kept under `logs/runs60/`.
- **Candidate audit and staging tools** — Added automatic deterministic data auditing in `brain/dataset_tools.py` (checking malformed rows, duplicates, and confusability), staged candidate review reports (`datasets/review_candidates.py`), and balanced candidate promotion across dataset splits.
- **MayaNode event/memory producer + outbox sync (Step 3)** — Added local validation and durable outbox queueing (`~/Maya/Node/outbox.json`) for MayaNode events and memories via `services/node/events.py` and `memory_producer.py`. `NodeSyncManager._sync_once` coordinates batch uploads, server reconciliation, and non-blocking background synchronization without dropping data when offline.
- **MayaNode inbound memory merge** — `NodeSyncManager._apply_incoming_changes` hands `changes["memory"]` to `ContextManager.apply_remote_memory_changes`, which accepts only `semantic_memory:*` keys, re-embeds locally, dedups against the existing store and inserts with `source="mayanode_sync"`; outgoing, `_sync_memory_to_node` mirrors only `user_stated` fact/preference memories (no embeddings, no compaction summaries). Incoming `changes["events"]` are intentionally not applied.
- **MayaNode versioned protocol layer** — `services/node/protocol.py` implements the contract in `docs/PROTOCOL_CONTRACT.md` (`protocol_version=1`, envelope validation, event-type registry, request builder, response version check, change-ordering check); `NodeClient.sync` validates outgoing events and the response (`SyncResult.from_response`) and adds `health()`.
- **MayaNode discovery + sync scaffolding** — Added background endpoint discovery, heartbeat connectivity, and atomic cursor persistence (`~/Maya/Node/sync_state.json`, `device_id.txt`) in `services/node/`, operating non-blockingly with graceful degradation when disabled.
- **Shutdown and restart skill** — `skills/system/power.py` now handles the `shutdown`/`restart` intents (previously answered by the LLM, nothing happened) by asking "say yes to confirm"; `Router.dispatch` calls `resolve_pending` first so a one-shot request (30 s TTL) is confirmed, declined or dropped by the next utterance, and confirm runs `shutdown /s` or `/r /t 10` (no `/f`) in the executor.
- **Lock screen skill** — `lock_screen` intent routed to `skills/system/lock_screen.py` (`LockWorkStation` via ctypes; apology on non-Windows), immediate by design with no confirmation because it is reversible.
- **Spoken timer reminder text** — `timer._extract_reminder` captures "remind me to X" (duration stripped, max 120 chars) and the alert speaks "Time's up, senpai! Reminder: X."

### Improvements
- **Ollama GPU Residency & VRAM Budget Optimization** — Resolved concurrent GPU/VRAM contention between Ollama `llama3.2` and Kokoro TTS on Windows by defaulting `num_ctx = 2048` in `config/settings.py`. Trimming ~600 MB of unneeded KV cache enabled 100% GPU transformer layer placement, reducing conversational TTFA by 58.2% (1,789 ms to 747 ms) and increasing generation speed to 30.2–32.8 tok/s with zero timeouts.
- **Live Runtime Ollama GPU Contention & VRAM Attribution Audit** — Isolated Windows 11 performance bottlenecks: eliminated a 2.0-second IPv6 loopback delay by standardizing `base_url` to direct IPv4 `http://127.0.0.1:11434`, confirmed Kokoro timeouts were triggered by PCIe bus saturation during mixed CPU/GPU layer offloading, and verified CPU-bound BGE semantic search introduces zero VRAM contention.
- **Kokoro Timeout Fault-Containment & Recovery** — Eliminated asyncio event loop freezes during Kokoro synthesis timeouts. When `asyncio.wait_for` expires, the worker is marked stale and returns immediately without blocking on `_kokoro_lock` (slashing loop lag from ~98 s to 86 ms), while pipeline resets are safely deferred off the event loop thread.
- **Kokoro Execution Isolation Audit** — Empirical 5-mode benchmark (100 turns) confirmed concurrent GPU Kokoro + Ollama streaming is optimal (median TTFA 1,149 ms, 100% reliability). CPU isolation (+150% TTFA) and sequential scheduling (+76% TTFA) were rejected, confirming the intermittent timeout was an isolated startup paging transient.
- **Ollama Latency Bridge Attribution Audit** — Latency and concurrency benchmark verified isolated Ollama TTFT at ~300 ms with generation throughput at 34–40 tok/s. Model load overhead is negligible (2–5 ms with `keep_alive=60m`), prompt evaluation absorbs 800+ tokens in 25–45 ms via prefix caching, and concurrent Kokoro synthesis was identified as the primary contributor to GPU resource contention.
- **ContextManager Shared Local BGE Migration** — Migrated conversational semantic memory in `brain/conversation.py` from HTTP Ollama embeddings to the shared in-process `LocalEmbeddingProvider` (`BAAI/bge-small-en-v1.5`), reclaiming 376 MB host RAM, dropping warm embed latency by 40% (p95 39.6 ms), and adding dimension-mismatch guards to `brain/vector_store.py`.
- **Stale WebSocket Client Disconnect Recovery** — Handled renderer disconnects in `services/ws_server.py` by immediately signalling `_audio_done_event` when the last client disconnects, releasing blocked `wait_for_audio_done()` calls within ~50 ms instead of hanging for the full 30-second safety timeout.
- **Eager Kokoro CUDA Warmup** — Initialized shared Kokoro `KPipeline` during startup with a silent forward pass (`"Hi."`) via thread-safe `ensure_kokoro_warmed()`, absorbing cold CUDA kernel compilation and activation buffering to reduce first-utterance TTS latency from 5,883 ms to 320 ms (−94.6%).
- **Local In-Process Semantic Embedding Inference** — Implemented CPU-bound `LocalEmbeddingProvider` using `BAAI/bge-small-en-v1.5` in `brain/embeddings.py`, reducing semantic retrieval latency from ~1,108 ms to 25–35 ms (−97%) with 0.0 MB VRAM usage and improving router test-set accuracy to 98.3%.
- **Test suite consolidation and cleanup** — Full regression suite passing at **170 passed** (`pytest brain services/llm -q`). Eliminated Python SyntaxWarnings in `brain/router/test_router_boundaries.py` (replaced literal identity comparisons `0.16 is None` with semantic equality / direct checks). Remaining warnings are external Keras/TensorFlow and conversational test logger messages.
- **Router failure-matrix output snapshot** — The files labeled seed1, seed2, seed3, and seed1_repeat each report 2/60 failures, but all four JSON files record `seed=1337` and identical combined and training hashes. They are same-seed outputs; distinct-seed provenance is unverified, so these files do not establish cross-seed consistency or current behavior after subsequent source changes.
- **Documentation realigned with source** — `docs/architecture.md` and `README.md` updated to reflect the active VE11 hybrid semantic router default, CUDA Kokoro TTS integration, hardened expression parser, and 170 passing tests.
- **Router safety gates** — `CommandIR.executable` is the single gate for running a skill; `Router.dispatch` routes non-executable IRs to the LLM, `NEEDS_CLARIFICATION` to `_clarify`, and fails closed when a `requires_confirmation` IR reaches a handler that does not self-confirm (`power.py`, `notepad.py`); `SkillRegistry.resolve` and `LegacySkillAdapter` refuse non-executable IRs; `SkillResult.meta` carries `action`/`_no_history`.
- **Entity extractors mirror skill parsers** — `brain/router/entities.py` (`duration`, `message`, `location`, `target`, `query`) accepts only what `timer.py`/`weather.py` can parse (first match per unit, number words up to sixty, zero ⇒ none); deterministic values win over LLM strings; the LLM prompt lists allowed entity keys per operation.
- **LLM routing prompt hardening** — `llm_fallback._build_prompt` adds per-operation descriptions and strict routing rules (active command only, computer scope vs physical world, no nearest-neighbour guessing, preserve legitimate commands) so narratives, complaints, and physical-device requests ("turn off the porch light", "lock up the shop") route to `unknown`; boundary tests live in `brain/router/test_router_boundaries.py` and skip when Ollama is not running.
- **Classifier margin exposed** — `IntentEngine.classify` returns `second_intent`, `second_confidence` and `margin` from the same averaged ensemble distribution (`None` for guard/keyword decisions) so the router can gate on it.
- **Ollama residency diagnostics** — `services/llm/ollama_lifecycle.py` logs per-turn COLD/warm status, load/prompt/generation tok/s and gap since the last chat, plus a background `/api/ps` and CUDA-memory snapshot; diagnostics only, never raises.
- **TTS device and LLM model defaults** — `config.tts.device` is now defined as `"cpu"` (`_resolve_tts_device`; `KPipeline(device=...)` is passed only if the installed kokoro accepts it) and `config.llm.model` is `llama3.2`.
- **Barge-in history** — interrupted LLM turns now record only the phrases whose playback started (`_spoken_phrases`) while finished turns record the full reply (`_reply_finished`).
- **Error strings and tags in history** — `query()` error replies set `intent["_no_history"]` (spoken, not stored) and `Processor` stores and broadcasts tag-stripped text for both skill and LLM replies.
- **Log volume** — `main.py` writes `logs/maya.log` through a `RotatingFileHandler` (5 MB × 3 backups) and sets the `httpx`/`httpcore`/`websockets`/`urllib3`/`tensorflow` loggers to WARNING to drop per-request noise.
- **Intent hard negatives and router eval coverage** — 55 hand-written hard negatives (`unknown` 19, `smalltalk` 30, `general_query` 6) targeting `set_timer`/`lock_screen`/`get_weather` lexical traps (alarm clock radio, clock/time statements, lock/app/weather mentions) promoted via `dataset_tools candidates promote`; `datasets/router_eval/cases.jsonl` expanded from 20 to 50 cases covering OOS/adversarial, paraphrase, ambiguous-valid, context, clarification, entity and LLM-fallback categories.
- **Deterministic intent training** — `_train_pytorch`/`_train_tf` seed from `_SEED` (torch, numpy, python, a seeded `DataLoader` generator, `tf.keras.utils.set_random_seed`) and the seed is part of `_dataset_fingerprint`, so saved models retrain once and later retrains reproduce; `eval_ir` output now includes a `model_digest` (hashes of the loaded PyTorch/TensorFlow weights and labels) to prove two runs scored the same model.
- **`eval_ir` model digest in JSON output** — `model_digest` is now computed before the report is printed, so it appears in the JSON (previously stderr only); it hashes the loaded PyTorch/TensorFlow weights, vocab and labels, adds a `combined` value built only from those artifacts, and records `seed` (`MAYA_SEED`) and the training fingerprint as metadata.
- **Router eval: statement-row regressions** — `datasets/router_eval/cases.jsonl` gains OOS cases for "i should lock up the shop before i go", "she talked for ninety minutes" and "the google search results were useless today" (eval only; no training rows added, no `lock_screen` confirmation).
- **Idle fidget pacing** — `avatar.js` holds automatic fidgets for a 5-minute post-launch calm period, gives `lookAround`/`idle`/`cuteThink`/`stretch` growing per-gesture cooldowns, keeps `stretch` out until 10 minutes of continuous idle and `waving` out of the random pool until a forced wave after 30 minutes idle, and suppresses fidgets while the gaze controller is observing.

### Architecture
- **AutoPhage Archival to `.maya/maintenance/` & Storage Audit (`docs/AUTOPHAGE_RESUMPTION_GUIDE.md`)** — Shelved AutoPhage maintenance subsystem from `skills/maintenance/` to `.maya/maintenance/` to preserve complete state, tests, and git branches. Pruned 16 dormant worktrees, purged 58 XML test reports, removed redundant `.bak` files, and staged deletion of stray `orchestrator.py\``, reclaiming ~396.3 MB of workstation disk space (`.maya/reports/repository-storage-growth-audit-20261030.md`).
- **Merged intents** — `open_app`/`open_website` → `open_target`, `note_create`/`note_append` → `note_write`, `note_read`/`note_list`/`note_open` → `note_view`, `set_reminder` → `set_timer`; skills decide the sub-operation from wording and `dataset_tools migrate-legacy-intents` relabels retired ids across splits and candidates. `help` and `unknown` are live intents again (see `docs/CONTRIBUTING.md`).
- **Config-driven command registry** — `config/command_domains.json` (25 `domain.operation` entries with entities, `target_mode`, `requires_confirmation`, semantic seeds) is a projection of the skill-mode intents in `datasets/intents.json`; `CommandRegistry`/`load_specs` validate it at load and reject a seed shared by two operations; the vector corpus is fingerprinted against it and a stale corpus only warns.
- **Command-level retrieval** — semantic scoring collapses per-seed vectors to one score per `domain.operation` before the top-k cut; margin is best minus second-best distinct command (`schemas.aggregate_by_command`).
- **Listening state broadcast** — `main.on_speech` broadcasts `state:listening` only when Maya is not PROCESSING/SPEAKING, empty STT resets to IDLE with baseline behavior, and the FSM no longer overwrites an in-flight turn, giving the sequence `listening → processing → speaking → idle`.
- **WebSocket last-state replay** — `ws_server` records `_last_state` on every `broadcast_state` (even with no clients, default `idle`) and `_handler` sends it to each new client, so the frontend's `_currentBackendState` is set at connect instead of staying `null` until the first broadcast.
- **Barge-in during processing and filler** — `state.can_interrupt()` allows PROCESSING with a live registered speech task, `on_speech` snapshots it instead of `is_speaking()`, and `query()` re-sets `_filler_done` in a `finally` so a cancelled filler never blocks the first phrase.
- **Timer alert routing** — the alert speaks through the `Speaker` injected by `Router` under `run_interruptible`, is queued on the command worker via `queue_manager.put_job` so it runs in order with commands, and the expired timer is removed from `_timers` before the alert.
- **Unreferenced background tasks** — `main.py` keeps `ws_task` with `_on_ws_done` failure logging and `ContextManager` keeps `_bg_tasks`.
- **Duplicate elongation helper removed** — `llm_service.py` keeps only the non-recursive `_elongation_re_sub` definition.
- **Sleep phrase matching centralised** — sleep-command detection moves from a `main.py` substring set to `core.wake_word.is_sleep_command`, next to the wake/barge-in matcher (importable without pulling in Kokoro); `main.on_speech` calls it instead of `_SLEEP_TRIGGERS`.
- **Shared spoken confirmation matcher** — `core/confirmation.py` (`is_confirm`/`is_deny`, whole-utterance yes/no phrases) is used by `power.py` and `notepad.py`; each skill still owns its own one-shot pending request and TTL, and `Router.dispatch` calls both resolvers before intent routing.
- **Frontend arbitration layers** — `expression-controller.js` (per-key layers `BASE<EMOTION<ACTION<LIPSYNC<BLINK`), `animation-controller.js` (bone ownership `BASE<FIDGET<ACTION` with a 350 ms handoff), `life-motion-controller.js` (breathing/posture/shoulders/hips at BASE tier) and `gaze-controller.js` (attention session, boredom ramp, eye/head offsets) are shared singletons driven from `main.js`'s single frame loop.

### Issues
- **Classifier failure log growth and Git tracking** ([#30](https://github.com/owner/repo/issues/30)) — [Verification pending] The current worktree contains changes to redirect new failure records to a local path and bound retention, plus local regression tests. The available test reports predate these changes, so the tracked-log privacy and growth fix is not yet marked resolved.
- **LLM fallback confidence contract** — [Potential; runtime-unverified] Missing or malformed confidence is deliberately treated as 0.0 by `validate_raw_llm_output`, while the fallback prompt requires a numeric confidence. The previously cited `diag_llm_seed*.txt` files are absent; verify actual model outputs before changing this fail-closed behavior.
- **Power confirmation and countdown** — [Potential] Confirmation is one-shot and accepts a bare confirmation phrase; a 10-second OS shutdown/restart countdown has no voice abort. No unintended power action is demonstrated; decide whether cancellation during the countdown is a product requirement before changing the flow.
- **Wake window boundary** — [Potential; static behavior] Wake recognition uses fixed, non-overlapping two-second windows, so a phrase split across windows may be missed. Runtime frequency has not been established.
- **Sparse classifier classes** — [Validation pending] In the current data snapshot, 28 of 41 intents are below their `min_examples` target. The cited recall/accuracy metrics are stale, and `datasets/training/candidates.jsonl` is currently empty; measure current per-class performance before changing training data.
- **Skill dispatch interruption gap** — [Limitation] Skill work before its first speech call is not registered as an interruptible task; a barge-in or sleep request may not cancel in-flight pre-speech work.
- **Critical-path latency** — [Potential; current impact unmeasured] Semantic-memory embedding can precede the first LLM token when memories exist, and streamed speech waits for per-phrase playback completion. Existing timing instrumentation can be used to establish impact before optimization.
- **Node backlog drain rate** — [Conditional limitation] Sync uploads at most 200 events and 200 memory keys per round and waits for the configured interval between successful rounds. Node sync is disabled by default; no material backlog is demonstrated.
- **Recent conversation window is not persisted** — [Limitation] The 50-entry recent history is in-memory and is lost on restart; durable semantic memory follows a narrower write policy.

Accepted limitations (not active defects): Inputs of three tokens or fewer may be decided by keyword rules before the classifier; the active router uses `CommandUnderstander`, while `HybridIntentEngine`, `shadow_mode` and `hybrid_domains` remain an unwired compatibility surface; the local embedding provider auto-seeds a stale command corpus; `media.mute` stays on the legacy route; Google STT is online-only; idle fidget tuning, screen-attention input and extra VRMA animations are optional/manual-only.

Validation and deployment debt (not reproduced): Unverified are production asset copying with a build, Electron's actual WebSocket Origin and no-Origin handling, packaged-client behavior, Windows power/lock/screenshot and Electron launch, named app mappings, and browser-origin rejection logging. Echo/self-transcription, wave timing, VRM expression-name compatibility and recipe morph persistence need model/runtime evidence before being treated as defects. The Kokoro path shares a locked pipeline; timed-out native work is not forcibly terminated and CPU fallback uses a separate pipeline, with resource impact unmeasured.

Technical debt: Training-path and migration examples match the canonical `datasets/training/` layout and `_LEGACY_INTENT_MAP`; the unreferenced `frontend/package_electron.json` was removed (`frontend/package.json` and its lockfile are active); `_tmp_diag_llm.py` is absent and `diag.py` is kept as a router diagnostic; tracked runtime/failure logs, historical evaluation artifacts and router case files are retained; the September 28 report records 817 candidate rows while `datasets/training/candidates.jsonl` holds 0 (last modified October 21); tests, test configuration and reports stay local-only under `.maya/` and are absent from clean checkouts.

# Changelog

All notable changes to MayaVE are documented here.

## [Unreleased]

### Features
- **Command IR router pipeline (opt-in)** — `brain/router/understand.py::CommandUnderstander` produces a `CommandIR` (`READY`/`NEEDS_CLARIFICATION`/`UNKNOWN`/`REJECTED`, `brain/router/ir.py`) through context rewrite (`context.py`) → guards → classifier confidence+margin gate → semantic retrieval (`semantic_router.py`, `command_vector_store.py`, separate SQLite file + fingerprint sidecar) → LLM fallback (`llm_fallback.py`, validated by `validate.py` against `config/command_domains.json`) → deterministic entity extraction (`entities.py`). Enabled with `config.router.backend = "hybrid"` (default `"legacy"`); `Processor._classify` falls back to the legacy classifier on any failure. A low-confidence command ends `UNKNOWN`, never a forced intent.
- **Router evaluation tooling** — `brain/router/eval_router.py` (retrieval sweeps, `--seed` for the command corpus), `eval_ir.py` (false-execution rate as primary metric, per-case output, `model_digest`), `failure_matrix.py` (cross-seed failure frequency), `diag.py`, and `datasets/router_eval/cases.jsonl` (60 cases); run outputs are kept under `logs/runs57/` and `logs/runs60/`.
- **Candidate audit and staging tools** — `brain/dataset_tools.py` runs an automatic deterministic audit (malformed, duplicate, contradiction, overly generic, keyword/vocabulary confusability, `help`/`unknown` restoration checks, boundary phrases, templates, diversity; optional capped LLM judgment) after generation and via `candidates audit`; `datasets/stage_data.py` stages hand-written rows/cases with leak and near-duplicate checks (dry run by default); `datasets/review_candidates.py` writes a read-only review report; `candidates promote` now splits ≈80/10/10 per intent with cross-split dedup.
- **MayaNode event/memory producer + outbox sync (Step 3)** — `services/node/events.py::record_event()` and `services/node/memory_producer.py::record_memory()` are the only application-facing entry points for data bound for MayaNode: both validate locally (`services/node/protocol.py`), stamp a UTC timestamp and a unique `event_uid`, and queue into a new durable local outbox (`services/node/outbox.py`, `~/Maya/Node/outbox.json`, atomic `.tmp` + replace) rather than calling `/sync` directly. `NodeSyncManager._sync_once` now pulls up to `config.node.max_events_per_sync`/`max_memory_per_sync` pending items per round, pushes them alongside the cursor, and reconciles the outbox against the response — only items the server actually settled this round (any terminal event status; the exact `(key, updated_at)` pair sent for memory) are removed, so a batch cap, a mid-round crash, or Node staying offline never loses queued data; the cursor still only ever advances per the Step 2 contract. Adds the first real MayaVE event type, `mayave.turn_completed` (`{intent: string}`), registered identically on both sides; `protocol.ping` is unchanged. `config.node.enabled` still defaults to `False`, and recording events/memory never depends on the sync manager running or Node being reachable.
- **MayaNode inbound memory merge (Step 4)** — `NodeSyncManager._apply_incoming_changes` hands `changes["memory"]` to `ContextManager.apply_remote_memory_changes`, which accepts only `semantic_memory:*` keys, re-embeds locally, dedups against the existing store and inserts with `source="mayanode_sync"`; outgoing, `_sync_memory_to_node` mirrors only `user_stated` fact/preference memories (no embeddings, no compaction summaries). Incoming `changes["events"]` are intentionally not applied.
- **MayaNode versioned protocol layer (Step 2)** — `services/node/protocol.py` implements the contract in `docs/PROTOCOL_CONTRACT.md` (`protocol_version=1`, envelope validation, event-type registry, request builder, response version check, change-ordering check); `NodeClient.sync` validates outgoing events and the response (`SyncResult.from_response`) and adds `health()`.
- **MayaNode discovery + sync scaffolding (Step 1)** — `services/node/` (`discovery.py`, `client.py`, `identity.py`, `sync_state.py`, `sync_manager.py`) adds discovery (`GET /status` probed against a configured `base_url` then an ordered candidate list), connection (`POST /heartbeat`), and an empty-payload `POST /sync` loop that persists/advances a cursor (`~/Maya/Node/sync_state.json`, atomic `.tmp` + replace) and a stable `device_id` (`~/Maya/Node/device_id.txt`) across restarts. `NodeClient` is auth-ready (`Authorization: Bearer` header hook, unused by MayaNode today). `node_sync_manager` runs as a background task in `main.py`, backoff-guarded and never raising even when MayaNode is offline or `config.node.enabled=False` (default). No MayaVE application data (events/memory/intents) is wired through yet — see `services/node/sync_manager.py`'s module docstring.
- **Shutdown and restart skill** — `skills/system/power.py` now handles the `shutdown`/`restart` intents (previously answered by the LLM, nothing happened) by asking "say yes to confirm"; `Router.dispatch` calls `resolve_pending` first so a one-shot request (30 s TTL) is confirmed, declined or dropped by the next utterance, and confirm runs `shutdown /s` or `/r /t 10` (no `/f`) in the executor.
- **Lock screen skill** — `lock_screen` intent routed to `skills/system/lock_screen.py` (`LockWorkStation` via ctypes; apology on non-Windows), immediate by design with no confirmation because it is reversible.
- **Spoken timer reminder text** — `timer._extract_reminder` captures "remind me to X" (duration stripped, max 120 chars) and the alert speaks "Time's up, senpai! Reminder: X."
- **Hybrid Semantic Router** — Hybrid router wired into Processor (opt-in via config.router.backend="hybrid")

### Improvements
- **Documentation realigned with source** — `docs/architecture.md` is rewritten from the code (router/IR/entity/LLM/MayaNode/data/testing sections, repo tree, implementation-status table; the raw trace notes in the old §4.1 are replaced) and `README.md` is rewritten for the current VE11 state (setup, run, tests, status, limitations).
- **Router safety gates** — `CommandIR.executable` is the single gate for running a skill; `Router.dispatch` routes non-executable IRs to the LLM, `NEEDS_CLARIFICATION` to `_clarify`, and fails closed when a `requires_confirmation` IR reaches a handler that does not self-confirm (`power.py`, `notepad.py`); `SkillRegistry.resolve` and `LegacySkillAdapter` refuse non-executable IRs; `SkillResult.meta` carries `action`/`_no_history`.
- **Entity extractors mirror skill parsers** — `brain/router/entities.py` (`duration`, `message`, `location`, `target`, `query`) accepts only what `timer.py`/`weather.py` can parse (first match per unit, number words up to sixty, zero ⇒ none); deterministic values win over LLM strings; the LLM prompt lists allowed entity keys per operation.
- **Classifier margin exposed** — `IntentEngine.classify` returns `second_intent`, `second_confidence` and `margin` from the same averaged ensemble distribution (`None` for guard/keyword decisions) so the router can gate on it.
- **Ollama residency diagnostics** — `services/llm/ollama_lifecycle.py` logs per-turn COLD/warm status, load/prompt/generation tok/s and gap since the last chat, plus a background `/api/ps` and CUDA-memory snapshot; diagnostics only, never raises.
- **TTS device and LLM model defaults** — `config.tts.device` is now defined as `"cpu"` (`_resolve_tts_device`; `KPipeline(device=...)` is passed only if the installed kokoro accepts it) and `config.llm.model` is `llama3.2`.
- **Barge-in history** — interrupted LLM turns now record only the phrases whose playback started (`_spoken_phrases`) while finished turns record the full reply (`_reply_finished`).
- **Error strings and tags in history** — `query()` error replies set `intent["_no_history"]` (spoken, not stored) and `Processor` stores and broadcasts tag-stripped text for both skill and LLM replies.
- **Log volume** — `main.py` writes `logs/maya.log` through a `RotatingFileHandler` (5 MB × 3 backups) and sets the `httpx`/`httpcore`/`websockets`/`urllib3`/`tensorflow` loggers to WARNING to drop per-request noise.
- **Intent hard negatives and router eval coverage** — 55 hand-written hard negatives (`unknown` 19, `smalltalk` 30, `general_query` 6) targeting `set_timer`/`lock_screen`/`get_weather` lexical traps (alarm clock radio, clock/time statements, lock/app/weather mentions) promoted via `dataset_tools candidates promote`; `datasets/router_eval/cases.jsonl` expanded from 20 to 50 cases covering OOS/adversarial, paraphrase, ambiguous-valid, context, clarification, entity and LLM-fallback categories.
- **Deterministic intent training** — `_train_pytorch`/`_train_tf` seed from `_SEED` (torch, numpy, python, a seeded `DataLoader` generator, `tf.keras.utils.set_random_seed`) and the seed is part of `_dataset_fingerprint`, so saved models retrain once and later retrains reproduce; `eval_ir` output now includes a `model_digest` (hashes of the loaded PyTorch/TensorFlow weights and labels) to prove two runs scored the same model.
- **`eval_ir` model digest in JSON output** — `model_digest` is now computed before the report is printed, so it appears in the JSON (previously stderr only); it hashes the loaded PyTorch/TensorFlow weights, vocab and labels, adds a `combined` value built only from those artifacts, and records `seed` (`MAYA_SEED`) and the training fingerprint as metadata.
- **Router eval: statement-row regressions** — `datasets/router_eval/cases.jsonl` gains OOS cases for "i should lock up the shop before i go", "she talked for ninety minutes" and "the google search results were useless today" (eval only; no training rows added, no `lock_screen` confirmation).

### Architecture
- **Merged intents** — `open_app`/`open_website` → `open_target`, `note_create`/`note_append` → `note_write`, `note_read`/`note_list`/`note_open` → `note_view`, `set_reminder` → `set_timer`; skills decide the sub-operation from wording and `dataset_tools migrate-legacy-intents` relabels retired ids across splits and candidates. `help` and `unknown` are live intents again (see `docs/CONTRIBUTING.md`).
- **Config-driven command registry** — `config/command_domains.json` (25 `domain.operation` entries with entities, `target_mode`, `requires_confirmation`, semantic seeds) is a projection of the skill-mode intents in `datasets/intents.json`; `CommandRegistry`/`load_specs` validate it at load and reject a seed shared by two operations; the vector corpus is fingerprinted against it and a stale corpus only warns.
- **Command-level retrieval** — semantic scoring collapses per-seed vectors to one score per `domain.operation` before the top-k cut; margin is best minus second-best distinct command (`schemas.aggregate_by_command`).
- **Listening state broadcast** — `main.on_speech` broadcasts `state:listening` only when Maya is not PROCESSING/SPEAKING, empty STT resets to IDLE with baseline behavior, and the FSM no longer overwrites an in-flight turn, giving the sequence `listening → processing → speaking → idle`.
- **WebSocket last-state replay** — `ws_server` records `_last_state` on every `broadcast_state` (even with no clients, default `idle`) and `_handler` sends it to each new client, so the frontend's `_currentBackendState` is set at connect instead of staying `null` until the first broadcast.
- **Barge-in during processing and filler** — `state.can_interrupt()` allows PROCESSING with a live registered speech task, `on_speech` snapshots it instead of `is_speaking()`, and `query()` re-sets `_filler_done` in a `finally` so a cancelled filler never blocks the first phrase.
- **Timer alert routing** — the alert speaks through the `Speaker` injected by `Router` under `run_interruptible`, is queued on the command worker via `queue_manager.put_job` so it runs in order with commands, and the expired timer is removed from `_timers` before the alert.
- **Unreferenced background tasks** — `main.py` keeps `ws_task` with `_on_ws_done` failure logging and `ContextManager` keeps `_bg_tasks`.
- **Duplicate elongation helper removed** — `llm_service.py` keeps only the non-recursive `_elongation_re_sub` definition.
- **Sleep phrase matching centralised** — sleep-command detection moves from a `main.py` substring set to `core.wake_word.is_sleep_command`, next to the wake/barge-in matcher (importable without pulling in Kokoro); `main.on_speech` calls it instead of `_SLEEP_TRIGGERS`.
- **Shared spoken confirmation matcher** — `core/confirmation.py` (`is_confirm`/`is_deny`, whole-utterance yes/no phrases) is used by `power.py` and `notepad.py`; each skill still owns its own one-shot pending request and TTL, and `Router.dispatch` calls both resolvers before intent routing.

### Fixes
- **Over-broad `google search` keyword** — removed from `search_web` in `datasets/intents.json`, so statements mentioning "google search" no longer reach `search_web` at confidence 1.0 via `keyword_fallback`; `search for`, `look up` and the `google <topic>` extraction are unchanged.
- **Empty-target fallback never triggers** — `_extract_target` returns `""` when a trigger matched but nothing followed it, so `google_search`/`open_app`/`open_website` ask for a target instead of using the trigger word; utterances with no matching trigger keep the whole-utterance fallback.
- **Weather location and code gaps** — `_extract_location` strips trailing time words ("London today" → "London", "for today" → auto-locate) and tolerates trailing `?.!`; `_WMO`/`_WMO_EXPRESSION` gain codes 56/57/66/67/77/85/86.
- **System info substring match** — RAM detection uses `\b(ram|memory)\b`, so "program" no longer triggers the RAM report; battery/cpu/disk/screenshot checks are word-boundary regexes too.
- **Perform action over-triggering** — the action-word guard skips question/definition phrasings (`_ACTION_QUESTION_RE`), so "what does nod mean" reaches the LLM while "can you nod" still performs it.
- **Screenshot intent ignored by system_info** — `execute` now passes the intent name to `_build_reply`, so "capture my screen" (intent `screenshot`) takes a screenshot instead of asking what information is needed.
- **Substring and prefix matching** — Sleep phrases move to `core.wake_word.is_sleep_command` ("go to sleep"/"goodbye"/"stop listening" anywhere, bare "sleep"/"bye" only as the whole utterance) and wake/barge-in triggers use `\b` regexes, so "asleep", "I didn't sleep well" and "Mayans" no longer match; `_keyword_fallback` matches on word boundaries with light inflection ("quite"→quit, "commute"→mute, "program"→ram no longer misroute); the greeting-prefix `startswith` clause is removed from the keyword-first guard (≤3-token rule stays); the dismissal guard tolerates leading fillers and trailing please/name ("no thanks please"); `open_website`, `timer` (including `"all"` inside "call") and `system_info` use word-boundary regexes.
- **Open website unknown sites** — `open_website` adds amazon/linkedin/stackoverflow to `_SITES` and resolves other targets through `_resolve_url` (explicit URL, dotted host, spoken "dot", or bare label → `https://www.<label>.com`); multi-word or junk targets now get a clarification reply instead of an invalid `https://…` URL.
- **HF offline flag import order** — `main.py` sets `HF_HUB_OFFLINE` (`setdefault "1"`) as its first statement, before any import that pulls in kokoro/huggingface_hub, so it now takes effect (huggingface_hub reads it at import time); the later `setdefault` in `llm_service.py` is redundant but harmless.
- **Blocking calls on the event loop** — `Processor` runs `IntentEngine.classify` via `run_in_executor`, `ContextManager` runs every semantic-store call (`has_records`, `search`, `find_similar`, `update`, `add`) via `run_in_executor`, `system_info` builds its reply (CPU sample, screenshot) in the executor and reports mood events back on the loop, and `expression_library.save_recipe` updates the cache immediately but writes the file on a single-thread writer (submission order preserved, last save wins); only startup work (`IntentEngine()` load/train, first `expressions.json` read) stays synchronous.
- **Kokoro rebuild blocks loop and resets wrong pipeline** — `Speaker._synthesise_guarded` rebuilds its pipeline in the executor and passes `on_timeout=lambda: None` to `_run_kokoro`, so a Speaker timeout no longer resets llm_service's pipeline.
- **Timer alert not serialized** — `timer._alert` queues the alert with `queue_manager.put_job`, so it runs on the command worker in order with commands and never overlaps a turn.
- **Reminder and timer parsing gaps** — `_words_to_digits` parses number words ("one hour"), "remind me to X" without a duration keeps X pending and `resolve_pending` takes the next utterance as the duration, and the label lookahead uses word boundaries so labels like "apple timer" are kept.
- **Residual audio_done stall** — `wait_for_audio_done` clears the shared Event and then compares `_stop_gen` with `_audio_sent_gen`, so a stop before entry returns immediately and a stop after entry sets the Event.
- **Skill-exception line stored in history** — the router's error fallback sets `intent["_no_history"]`, so it is spoken but not stored as an assistant turn.
- **Degenerate context topic and entity data** — `Processor` blanks `intent["target"]` when it equals the whole utterance before `observe_user_turn`, so `TOPIC`, `ENTITIES` and `LIKELY REFERRING TO` no longer echo the current utterance.
- **Decimals and versions split mid-token** — `_next_boundary` now waits when a `.` ends the buffer right after an alphanumeric, so "3.14" and "google.com" are no longer split into separate phrases.
- **Spurious Kokoro pipeline rebuild** — `Speaker._synthesise_guarded` rebuilds its pipeline only on a real timeout, using a `_NO_AUDIO` sentinel for "no audio produced".
- **expressions.json wipe on corrupt read** — `expression_library._load` records `_load_failed` and `_save_all` then refuses to overwrite the file; writes go through a `.tmp` file with atomic replace.
- **WebSocket broadcast set mutation** — `ws_server._broadcast` iterates a copy of `_clients` instead of the live set.
- **Stale utterance after sleep** — `Listener._process_frame` clears the in-progress utterance while SLEEPING.
- **Audio-done stalls** — the frontend sends `audio_done` when `vrm` is missing or decoding fails, `broadcast_stop_audio` sets the shared Event, and `_audioGen` drops audio whose decode finished after a stop.
- **Short exclamation over-expansion** — `_expand_short_exclamation` is skipped for `continuation` chunks so "Well, yes." keeps "yes." while a bare "Yes!" still expands.
- **Stale fidget timers and headTilt fighting actions** — the VRMA cleanup timer is guarded by mixer identity and `headTilt` is cancellable via `_headTiltStop`, halted when an ACTION animation starts.
- **Expression Lab default pinning** — only edited (`_dirty`) combinations are persisted on switch or Export, so browsing no longer pins generated defaults.
- **Timer duration double-count** — `timer._parse_duration` uses one pattern per unit (`hours?|hrs?`, `minutes?|mins?`, `seconds?|secs?`) so "5 minutes" no longer counts twice.
- **Timer name race and reminder hijack** — `_countdown`'s `finally` removes only its own `_timers` entry and `timer.execute` skips cancel/status word checks for `set_reminder`, so "remind me to stop by…" no longer cancels a timer.
- **Perform action animation** — `Processor` now broadcasts `intent["action"]` (set by `perform_action`) via `on_audio_start` (nod/giggle/sigh/shrug/wink).
- **Dismissal guard misroutes** — the dismissal guard is now an exact-phrase match (trailing `.!?,` stripped) instead of `startswith`, fixing misroutes of "note…", "nod…", "stop the timer" and similar.
- **Screenshot skill** — saves a timestamped file, auto-creates the folder, no longer calls the broken `logging.log`, and also triggers on intent `screenshot` ("capture my screen").
- **Sleep not persisting** — `Speaker.speak()` restores SLEEPING when it was sleeping on entry and `main.py` sets IDLE before the startup greeting, so Maya still starts awake and the wake word is now actually active while asleep.
- **Chat model idle unload** — `keep_alive` (`ollama_lifecycle.chat_keep_alive()`, default `"60m"`) is sent on every chat request and the chat warmup instead of Ollama's 5-minute default.
- **Startup greeting stall without a client** — `wait_for_audio_done` returns False immediately when no frontend client is connected instead of waiting 30 s.
- **Notepad content handling** — a `note_*` intent dispatches directly to its handler and `_extract_content` strips only the leading command phrase, so "take a note buy milk and write the report" keeps the whole content.
- **Missing dependencies and logs directory** — `websockets` and `pyperclip` added to `config/requirements.txt` and `main.py` creates `logs/` before logging setup.
- **Frontend reconnect leak** — `startBlinking()` clears `_blinkTimeout` and `startEyeMovement()` starts once per page (`_eyeLoopStarted`), so WS reconnects no longer double the blink/eye loops.
- **Clipboard import crash** — `skills/system/clipboard.py` imports `pyperclip` in a guarded `try`/`except ImportError` (same pattern as `play_music.py`), so a missing package only makes clipboard commands answer with an install hint instead of crashing startup through the Router import.
- **Open app has no name mapping** — `open_app` normalises the target ("the chrome browser please" → "chrome"), resolves spoken names through `_APP_TABLE` (calculator, file explorer, task manager, terminal, paint, settings, browsers, Office apps, VS Code, Discord/WhatsApp via protocol URIs) with ordered launch candidates, passes unknown names through unchanged, launches in the executor and replies with expression tags.
- **Notepad delete without confirmation** — `note_delete` now only asks "Say yes to confirm"; `notepad.resolve_pending` (called from `Router.dispatch` after the power and reminder resolvers) deletes the note on yes, keeps it on no and drops the one-shot request (30 s TTL) on anything else, and the note is spoken without its `_MMDD_HHMM` filename suffix.
- **Unrestricted WebSocket origin** — `ws_server` passes `config.ws_allowed_origins` (default: the Vite dev origin on `localhost`/`127.0.0.1:5173` plus clients that send no Origin header) to `websockets.serve`, so a browser page from any other origin is rejected at the handshake and can no longer send `interrupt`/`audio_done`; setting it to `None` disables the check.
- **Unpinned websockets import path** — `ws_server` no longer imports `websockets.server.WebSocketServerProtocol` (connections are annotated `Any`) and `requirements.txt` pins `websockets>=12.0,<16.0`.
- **Dead reminder skill and stray files removed** — `skills/utilities/reminder.py` (unreferenced; `set_reminder` routes to `timer.py`) is deleted, the unused `wikipedia` dependency is dropped from `requirements.txt`, and `.gitignore` loses its BOM and the stray `0.9.0`/`12.0` lines.
- **Config surface fully trimmed** — `STTConfig.model_size/device/compute_type`, `LLMConfig.provider/api_key/system_prompt`, and `TTSConfig.cpu_threads` have been removed from `config/settings.py` outright (they are no longer present as commented/unused fields); `STTConfig` now defines only `language`, `LLMConfig` only `model`/`base_url`/`max_tokens`/`temperature`, and `TTSConfig` has no `cpu_threads` field at all.
- **Listening state edge cases** — a LISTENING watchdog (`main.py`, registered via `core/state.py`'s new `add_observer()`) resets to IDLE after 15s with no follow-up; `queue_manager.put()` returns whether the command was actually queued so a full-queue drop resets immediately instead of relying on the watchdog alone; `avatar.js`'s `setAvatarState()` no longer resets the 30-minute idle timer on a bare `"listening"` blip that resolves to nothing.
- **Interrupted turn leaves unanswered user turn** — `llm_service.query()` records a short, clearly-out-of-character marker as the assistant turn when a barge-in cuts a reply off before anything was spoken, instead of leaving the user's turn with no paired reply in history at all.
- **Sleep race and startup log** — `core/turn_lifecycle.py`'s `rest()` (used by `Processor.handle()` and `llm_service._play_worker`) and `Speaker.speak()`'s finally block both now check `state.is_sleeping()` fresh at completion rather than trusting a stale snapshot, so a concurrent "go to sleep" is never silently overwritten back to IDLE; `Processor.handle()` also drops a queued command outright if she's already asleep by the time it's dequeued; `on_speech()`'s sleep-trigger calls `state.interrupt()` first to cleanly stop whatever's currently playing before speaking the goodbye line; `core/listener.py`'s startup log now reflects the actual FSM state instead of always claiming SLEEPING.
- **Skill-path barge-in** — `Processor.handle()`'s skill-response `Speaker.speak()` calls and `main.py`'s greeting/wake-up/sleep lines are now wrapped in `state.run_interruptible()`, so a barge-in during any of them cancels the task instead of only halting audio via the stop callback.
- **Avatar never visually sleeps** — `Speaker.speak()` broadcasts WS state `"sleeping"` once the goodbye line finishes; `frontend/js/websocket.js`'s `handleState()` reacts with `sleepAvatar()`/`wakeAvatar()` as the single source of truth for the avatar's visual sleep state, independent of the WebSocket connection.
- **LLM router fallback rejected clarifiable commands** — `CommandUnderstander._from_llm` validates command identity only, so a missing required entity now asks for clarification instead of REJECTED; null LLM entities are dropped in `validate_raw_llm_output`.
- **Escalated commands used the classifier's target** — `_from_spec` re-derives the target for the selected spec's legacy intent.
- **Hybrid shadow mode compared legacy with itself** — `aclassify(force_hybrid=True)` is used by `_shadow_compare`; the hybrid LLM branch now honours `LLM_MIN_CONF`.
- **Stale retired intent ids in context phase inference** — `_TASK_INTENTS` uses `open_target`/`note_write`/`note_view`.
- **Router fallback keep_alive** — `llm_fallback.route` uses `chat_keep_alive()`.
- **Obsolete router tests and one-off patch script removed** — media.mute fixtures, duplicate margin/IR tests, `RouterDecision`, `patch_command_domains.py`; its metadata edits are applied to `command_domains.json`.
- **LLM missing-entity clarification** — the LLM missing-entity clarification (this makes the earlier changelog claim true), the string DB path, and the processor target blanking.
- **Keyword shadowing in `get_time` and `farewell`** — `clock` is removed from `get_time` (it forced alarm clock radio, lobby clock and microwave clock phrasings to `get_time` at confidence 1.0, regardless of training data) and `tell me the time` is added so it is no longer shadowed by `general_query`'s `tell me`; `later` is replaced by `talk to you later`/`catch you later` on `farewell`, so "might snow later" no longer routes to `farewell`.
- **`Processor` could not be constructed** — `__init__` now sets `_speaker`, `_conversation` and `_router` (`Router(speaker)`, imported from `brain.router.dispatch`) and `_build_understander` is a `@staticmethod`; `handle()` already depended on all three and `Processor(speaker)` previously raised at startup.

### Issues
- **Short-input keyword path bypasses the classifier** — [Limitation] Inputs of three tokens or fewer take `keyword_short_input` and a keyword match wins over the ensemble at any confidence, so any over-broad keyword in `datasets/intents.json` misroutes regardless of training data; keywords must be phrase-level.
- **Hybrid router thresholds still placeholders** — [Limitation] The hybrid path is opt-in (`config.router.backend = "hybrid"`); `MIN_CONF`/`MIN_MARGIN`/`MIN_CONF_NO_MARGIN`/`LLM_MIN_CONF` in `understand.py` and `config.router` similarity/margin values have not been tuned from `eval_router` sweeps even though the eval tooling now exists.
- **Statement rows misfire at high confidence** — [Confirmed] In `logs/runs60/` all three seeds still turn "I set a timer for my kids once and they loved it" into a timer clarification and `she talked for ninety minutes` into one on two of three; seed 1 executes `web.search` for "my google search history is embarrassing"/"the google search results were useless today" and `system.lock` for "I should lock up the house before I leave"; fixing this needs training/eval work, not router changes (no training rows were added for the eval-only cases).
- **LLM fallback invents entity keys** — [Confirmed] On out-of-scope input the fallback often returns an operation with undeclared entity keys (e.g. `query` for `weather.current`), which validation turns into `REJECTED` (4–6 of 60 eval cases, scored as pass but flagged "overreach"); it also returns valid commands below `LLM_MIN_CONF` for paraphrases ("could you pull up spotify for me", "hey could you jot a quick memo that the dentist is at three" fail on all three seeds).
- **`HybridIntentEngine` is not wired** — [Limitation] No caller in `main.py`/`processor.py`; `config.router.shadow_mode` and `hybrid_domains` affect only that class, not `CommandUnderstander`, which is the runtime hybrid path.
- **Command corpus must be seeded manually** — [Limitation] A stale or unseeded command-vector corpus only logs a warning; the semantic tier then returns no candidates and every escalation goes straight to the LLM until `python -m brain.router.eval_router --seed` is run.
- **`mute` has no registry operation** — [Limitation] `command_domains.json` deliberately omits `media.mute`; a mute utterance relies on the classifier/keyword path (READY via the canned `legacy` route) and is invisible to semantic retrieval and the LLM fallback.
- **`eval_ir` confirmation counter** — [Potential] `run_eval` increments the module-level `confirm_errors` without a `global` declaration, so a case with an `expect.requires_confirmation` key would raise `UnboundLocalError`; no current case uses that key.
- **Node backlog drains one page per interval** — [Limitation] `NodeSyncManager` logs `has_more` but sleeps `sync_interval_s` between rounds and uploads at most 200 events/200 memory keys per round, so a large outbox or change feed drains slowly.
- **Skipped remote memory is not retried** — [Limitation] An incoming `semantic_memory:*` change that fails to embed is skipped after the cursor has advanced and is never re-requested.
- **Stale training-tool docstring and duplicate package file** — [Debt] `brain/train_intent.py`'s docstring still points at `config/{train,validation,test}_data.jsonl` (the code reads `datasets/training/`), and `frontend/package_electron.json` is an unreferenced older copy of `package.json`.
- **Tests are not documented as runnable from a clean checkout** — [Debt] `pytest` is absent from `config/requirements.txt`, there is no `pyproject.toml`/pytest config, `tests/` is gitignored while tests live under `brain/`, and `test_hybrid_router.py` reads `datasets/intents.json` by relative path (skips when absent).
- **Failure and candidate logs grow without bound** — [Debt] `logs/intent_failures.jsonl` appends every sub-0.65 classification (repeated eval runs add thousands of duplicate rows), and `candidates.jsonl` held 817 unreviewed candidates in the last `logs/candidate_review_report.txt`.
- **Skill dispatch phase still not interruptible** — [Limitation] A skill's own blocking work *before* it starts speaking (`weather.py`'s HTTP call, `system_info.py`'s 1s CPU sample) has no registered task yet, so `can_interrupt()` is False for that window; only once it reaches its own `Speaker.speak()` call does a barge-in (or a concurrent "go to sleep") actually stop it.
- **Stray reply after a mid-dispatch sleep command** — [Potential] If "go to sleep" lands while a skill is still in that uninterruptible dispatch phase, she'll still speak that skill's reply once dispatch finishes (ending back at SLEEPING correctly via `Speaker.speak()`'s fresh sleep check, but only after speaking one more line she probably shouldn't have).
- **Brief state flicker on a barged-in goodbye line** — [Potential] Calling one's name during the sleep goodbye line correctly ends at LISTENING, but the intermediate broadcast can be `"idle"` rather than a clean single transition, since `interrupt()`'s own tail runs after `Speaker.speak()`'s cancelled-finally has already broadcast once.
- **Late-connecting frontend can still briefly replay "listening"** — [Potential] `ws_server`'s `_last_state` can still be `"listening"` for the short window before the watchdog (or a real transcription) resolves it, though the watchdog now bounds that window to 15s instead of indefinitely.
- **Greeting rule shadows commands in keyword fallback** — [Potential] The `greet` rule ("hey maya", "hi maya", …) precedes intents that have no keyword rule (weather, clipboard, notes, joke), so when ML confidence is below 0.65 an utterance like "hey maya what's the weather" resolves to `greet`.
- **Energy fragmentation truncation** — [Confirmed] `_fragment_for_energy` truncates to 4 comma-fragments on excited/happy/angry final chunks, and the Speaker path passes whole multi-sentence text.
- **Echo and self-transcription** — [Potential] VAD and STT run while Maya speaks with no echo cancellation, so her own speech (e.g. "I'm Maya") can queue as a command, trigger self-barge-in or drop a pending power confirmation (setup-dependent).
- **Power confirmation fragility** — [Potential] The confirmation is one-shot so an STT mishearing of "yes" or Maya's own prompt picked up by the mic drops it (safe direction), the 10 s OS countdown has no voice abort, and graceful shutdown without `/f` can be blocked by apps with unsaved work.
- **Wake window boundary** — [Potential] The wake detector uses 2 s non-overlapping windows, so a wake word straddling a boundary is missed.
- **Kokoro concurrency and lazy init** — [Potential] Filler and first phrase synthesize concurrently on one pipeline (plus Speaker overlap), `_get_kokoro` lazy init is unlocked, a stuck native call cannot be killed (daemon thread orphaned), and Ollama/Kokoro/embeddings may contend for GPU if `tts.device` leaves `"cpu"`.
- **Latency on the critical path** — [Potential] The embedding call sits before the first LLM token when memories exist, the per-phrase WAV plus `audio_done` round trip creates inter-phrase gaps, and the chat model still unloads if idle beyond `keep_alive` (default 60 m) or evicted by Ollama (check `[TIMING] chat turn` COLD lines).
- **Cloud-dependent speech recognition** — [Limitation] Google STT is required for both utterances and the wake word, so Maya cannot run offline despite an otherwise local-first design.
- **Recent window not persisted** — [Limitation] The 50-entry conversation window is lost on restart; only semantic memories (narrow write policy) survive, and `VALID_MEM_TYPES` values goal/decision/relationship/project are never produced.
- **Duplicate Kokoro pipelines** — [Limitation] `Speaker` and `llm_service` each hold a `KPipeline` (deliberate, avoids cold reloads), duplicating RAM, or VRAM if the device changes.
- **Production build unsupported** — [Limitation] `vite build` does not copy `frontend/assets/` into `dist/` (no `publicDir`), so only dev-server mode is evidenced.
- **Idle fidget tuning unfinished** — [Limitation] Cooldown and threshold constants in `avatar.js` are still in flux and not final.
- **Rejected WebSocket origins are silent** — [Limitation] `main.py` sets the `websockets` logger to WARNING, so a handshake rejected for a disallowed origin is not logged (the avatar just stays on 💤 with a 403 in the browser console; the allowed origins are logged at startup), a packaged `file://` build would need its origin added, and any local non-browser process can still connect.
- **Wave and speech out of sync** — [Unverified] Per project notes the `wave` fires in `on_audio_start` after synthesis; a concurrent `asyncio.gather` fix was attempted and rolled back, and the current status cannot be re-verified from source.
- **Expression naming split** — [Unverified] The composer uses `joy/fun/sorrow` while `avatar.js` uses `happy/relaxed`, and which set the real VRM exposes (plus which `Fcl_*` morphs exist) is unknown, so one path may silently no-op.
- **Recipe persistence past 220 ms** — [Unverified] `_animateRecipeTo` stops writing raw morphs after 220 ms; if `expressionManager.update()` resets morphs bound to expressions, recipe faces would fade.
- **Ollama residency and GPU placement** — [Unverified] Actual keep-alive behavior, model availability and VRAM contention between Ollama and embeddings (Kokoro on CPU) are unchecked; use `ollama ps` and the COLD log lines.
- **Windows skills and Electron launch** — [Unverified] `shutdown.exe` invocation, lock screen, screenshots and an actual `npm run dev` Electron launch have not been run.
- **Nothing runtime-tested by the documentation audit** — [Unverified] Every fix in this changelog and all speech-recognition accuracy/latency, Kokoro thread-safety and echo behavior were checked by static inspection; the only runtime evidence is the eval outputs in `logs/` (router/IR runs on the author's machine); VRM/VRMA assets were Git LFS stubs.
- **WebSocket origin allow-list** — [Unverified] Electron's actual Origin header in dev (expected `http://localhost:5173`) and how the installed `websockets` version treats a `None` entry in `origins` were not run; a wrong value shows as the avatar staying on 💤.
